# CloudUDS — выпуски

Рабочие столы (VDI) на OpenUDS в VK Cloud: портал сотрудников, кабинет администратора, отказоустойчивая установка.
Этот репозиторий — **только выпуски**: скрипт установки, заметки к версиям и ключ проверки подписи. Пакеты версий
(`cloududs-X.Y.Z.tar`: код установщика и ролей, готовые образы контейнеров, подписанный манифест) приложены к
[выпускам](../../releases).

## Документация
[Документация](docs/README.md) — та же справка, что в кабинете администратора: начало работы, руководство
администратора, как устроена система, решение проблем, справочник и обслуживание.

## Установка
1. Создайте ВМ установщика в проекте VK Cloud: Ubuntu 24.04, 2 vCPU / 4 ГБ / 40 ГБ, в сети, из которой будут видны узлы.
2. На ней:
   ```
   curl -fsSLO https://raw.githubusercontent.com/jaland-hara/CloudUDS-release/main/install.sh
   sudo bash install.sh              # последний выпуск
   sudo bash install.sh 0.1.0-dev.3  # или конкретная версия
   ```
   Без доступа к GitHub с этой ВМ: скачайте пакет `cloududs-X.Y.Z.tar` со страницы [выпусков](../../releases) где угодно,
   перенесите на ВМ вместе с `install.sh` и выполните `sudo bash install.sh /путь/cloududs-X.Y.Z.tar`.
3. Скрипт напечатает команду SSH-туннеля и ссылку входа в мастер. Дальше мастер ведёт по шагам: профиль, подготовка облака, узлы и предпроверка, параметры, установка.

Команды на ВМ установщика: `sudo cloududs-installer link | status | logs | restart`, обновление — `sudo cloududs-installer <пакет новой версии>`.

## Пакеты ОС на узлах и прокси
Узлы ставят и обновляют пакеты Ubuntu через apt (Docker, MariaDB, HAProxy, обновления безопасности); образы контейнеров
приходят с ВМ установщика, интернет для них не нужен. Нужен доступ узлов к зеркалу Ubuntu.

**Может потребоваться прокси для apt**:
- в VK Cloud с некоторых плавающих IP (у пограничных узлов DMZ) региональные зеркала `*.clouds.archive.ubuntu.com`
  недоступны, а выход в интернет бывает нестабильным;
- в организации выход в интернет разрешён только через её прокси.

Мастер → «Узлы и предпроверка» → **«Прокси для пакетов ОС»**: тип (HTTPS — TLS до прокси, HTTP или SOCKS5),
адрес, порт, при необходимости пользователь и пароль (пароль хранится в зашифрованных секретах мастера). Прокси используется
**только apt** на узлах: предпроверка проверяет зеркало через него, шаг «Подготовка» записывает его в
`/etc/apt/apt.conf.d/80-cloududs-proxy` (права 0600) — им же пользуются «Обновить ОС узлов» и автообновления Ubuntu.
Остальной трафик (Let's Encrypt, база уязвимостей, S3, облако) через него не идёт.

Без прокси мастер сам переключает узел на `archive.ubuntu.com`, если зеркало облака с него недоступно, и повторяет загрузки
apt при обрывах; если и это не помогает — предпроверка покажет ошибку «Пакеты ОС» и подскажет задать прокси.

## Проверка подлинности
`install.sh` проверяет подпись манифеста пакета (Ed25519, ключ — [`release-pub.pem`](release-pub.pem), он же вписан в скрипт)
и контрольную сумму каждого файла **до** распаковки. Пакет, изменённый после выпуска, не установится.

> Сейчас выпуски подписаны ключом разработки (версии `0.x.y-dev.N`). Ключ для выпусков в эксплуатацию будет заменён и объявлен здесь.
