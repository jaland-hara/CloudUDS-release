# Наш кабинет и штатная админка UDS

*Как устроено*

> Чем штатные интерфейсы UDS отличаются от наших, что где делать и чего у нас пока нет.

## Главное различие

**Штатная админка UDS** (`/uds/adm/`) — конструктор объектов брокера: поставщик → сервис → менеджер ОС → транспорты → пул → публикация → группы. Каждый объект настраивается отдельно, согласованность между ними — забота администратора. **Наш кабинет** (`/admin/`) — сценарии: «дать группе стол», «сменить образ», «кто на каком столе», «что сломалось». Цепочку объектов UDS кабинет собирает сам и не даёт выбрать несовместимое. Кроме того, кабинет знает об облаке VK Cloud (образы, тома по ID, сети), в опции — о VMware vSphere (эталоны, хранилища, порт-группы) и о серверах вокруг брокера, чего в UDS нет вовсе.

Штатный портал доступен по ссылке с `?classic=1`.

| Сценарий | Штатный портал | Наш портал | Удобнее |
|----|----|----|----|
| **Список столов** | плитки сервисов, группы пулов | свои столы с состоянием | наша |
| **Как подключиться** | сотрудник выбирает транспорт у плитки | «В браузере» или «Через приложение», без технических названий | наша |
| **Перезагрузить стол или получить чистый** | кнопки, если разрешено в пуле | те же действия в меню стола: «Перезагрузить стол» и «Получить чистый стол», с подтверждением; разрешаются в пуле | одинаково |
| **Заявки на стол и программу** | нет | есть | наша |
| **Смена пароля, в том числе в AD** | нет | есть (для AD нужен LDAPS на контроллере домена) | наша |
| **Мета-пулы** | есть | есть: один значок, «через приложение / в браузере» | наша |
| **Доступ по календарю** | есть | нет | штатная |

## Что такое мета-пул

Мета-пул — один значок у сотрудника, за которым стоят несколько обычных пулов. Сотрудник нажимает «Бухгалтерия», а UDS сам решает, из какого пула выдать стол. Настройки мета-пула в UDS 5:

- **распределение:** поровну; по приоритету (сначала первый пул, остальные — когда он заполнен); туда, где больше свободных машин в процентах;
- **отказоустойчивость:** если пул недоступен, стол выдаётся из следующего;
- **транспорты:** автоматически, только общие для всех пулов или сгруппированные по метке;
- календарь доступа и текст отказа, как у обычного пула.

**У нас:** раздел «Мета-пулы» — сценарии вместо политик, прогноз, запасной пул по образцу, вывод пула из выдачи.

**Где пригодится:** один и тот же стол в двух зонах доступности (часть пулов для отказоустойчивости); переполнение — основной пул на SSD, запасной на HDD; разные сети для разных офисов под одним значком. Важно: личные постоянные столы остаются в своём пуле, поэтому мета-пул полезнее для столов «из общего набора».

## Второй фактор (MFA) в UDS

В UDS второй фактор подключается к способу входа (домен, собственные пользователи) и спрашивается на странице входа UDS после пароля. Наш портал использует эту же страницу входа, поэтому второй фактор, включённый в UDS, работает и для нашего портала. У нас нет только экрана настройки. Виды:

- **TOTP** — приложение-аутентификатор (Яндекс Ключ, Google Authenticator и т. п.), QR-код при первом входе;
- **E-mail** — код письмом через SMTP организации;
- **SMS через HTTP** — код через любой SMS-шлюз с HTTP API (адрес, параметры, авторизация настраиваются);
- **RADIUS OTP** — проверка кода внешним сервером RADIUS (например, корпоративная система одноразовых паролей).

Общие настройки: не спрашивать код из доверенных сетей (офис); запоминать устройство на заданное время; что делать с пользователем, у которого нет почты или телефона (пустить, не пускать, пустить только из определённых сетей).

**У нас:** раздел «Второй фактор» настраивает все четыре вида для сотрудников. Для входа в кабинет администратора — свой TOTP (раздел «Администраторы»).

## Что где делать

- **Каждый день — в кабинете:** пулы, образы, политики, пользователи и группы, поиск, состояние, сертификаты.
- **В штатной админке — только то, чего нет в кабинете:** календари доступа, уведомители, отчёты, конфигурация брокера, разбор логов сервисов и публикаций.
- **Не менять в штатной админке то, чем управляет кабинет:** транспорты пулов, менеджер ОС, сеть и шаблон сервиса. Кабинет узнает об этом только при следующем чтении, а его собственные данные о пуле (политика, диск, режим входа) могут разойтись с UDS.
