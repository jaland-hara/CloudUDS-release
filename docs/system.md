# Состав системы

*Как устроено*

> Что взято из OpenUDS и других проектов, что написано нами, где что работает и как ставится и обновляется.

## Из OpenUDS 5 (VirtualCable, лицензия BSD-3)

Основа системы: брокер выдаёт столы, туннель доставляет картинку, агент на столе управляет входом, клиент показывает стол.

| Компонент | Где работает | Как попадает в установку | Что изменено / дописано нами |
|----|----|----|----|
| **Брокер UDS** | узлы брокеров: контейнеры веб (REST API, порт 8000) и планировщик заданий, рядом memcached и локальный прокси к Galera | образ `cloududs/broker` из пакета выпуска: OpenUDS 5.0 (github.com/VirtualCable/broker, BSD-3) на закреплённом коммите, Python 3.12 / Django | патчи `broker/*.patch`: время кодов второго фактора (UTC), клиенты для РЕД ОС / Astra / Альт, имена томов OpenStack, данные ВМ пулов, включение и остановка столов, LDAPS и несколько контроллеров домена; транспорт «HTML5 RDP (Guacamole)»; провайдер «VMware vSphere» (ниже) |
| **Туннель UDS** | узлы туннелей (пара с VIP); в расширенном профиле инсталляции — ещё внешние туннели в DMZ; в минимальном — на единственной ВМ | образ `cloududs/tunnel`: OpenUDS 5 (Rust) на закреплённом коммите; узел подключает мастер через кабинет, дальше образ обновляет агент узла | сертификат узла для связи с брокером через фронты (mTLS); TLS поверх протокола туннеля на том же порту — для фильтров провайдеров туннель выглядит как HTTPS; ожидание рукопожатия 3 с вместо 0,2 с для медленных каналов |
| **Штатные веб-интерфейсы UDS** | в контейнере брокера: страница входа, классический портал, админка `/uds/adm/` | в составе образа брокера | вход используется как есть; классический портал заменён нашим: фронты переводят `/uds/page/services` на `/my/` |
| **Агент UDS (actor)** | на каждом рабочем столе (Windows, Linux) | пакеты `udsactor-*` в пакете выпуска; кабинет раздаёт их команде подготовки образа | пароль локальной учётки от менеджеров случайных паролей; сборка Linux под glibc 2.24 (Astra) |
| **Клиент CloudUDS (UDS Launcher + FreeRDP 3.27)** | компьютеры сотрудников: Windows, macOS, РЕД ОС, Astra, Альт | пакеты клиентов в пакете выпуска; портал раздаёт их сотрудникам | масштаб по DPI, физический размер монитора, плавный скролл, клавиши macOS, камера и микрофон на Mac, утечка памяти графики, вход NTLM и по сертификату (Kerberos PKINIT), метрики графики |

## Написано нами

Исходники — в приватном репозитории; заказчик получает подписанный пакет выпуска. Секретов в коде и пакете нет: пароли и ключи генерирует мастер установки и хранит зашифрованными.

| Компонент | Где работает | Как попадает в установку | Что изменено / дописано нами |
|----|----|----|----|
| **Мастер установки** | ВМ установщика: контейнер `cloududs-installer` (только 127.0.0.1:8200), данные в `/var/lib/cloududs-installer` | `install.sh` из репозитория выпусков ставит его из пакета (подпись проверяется до распаковки) | всё целиком: ресурсы VK Cloud, предпроверка, установка и обновление узлов по SSH, обновление ОС узлов |
| **Кабинет администратора и портал сотрудников** | узлы брокеров: кабинет (контейнер, порт 8100) и портал (отдельный контейнер, порт 8101, своя учётная запись БД без доступа к секретам кабинета); данные — в Galera | образ `cloududs/panel` из пакета | всё целиком: пулы, образы, политики, сети, пользователи, администраторы и второй фактор, уведомления, журнал и SIEM, состояние системы, сертификаты (выпуск Let’s Encrypt через VK Cloud DNS, Cloudflare или вручную), резервные копии; портал со столами, запросами и сменой пароля |
| **Провайдер «VMware vSphere» для UDS (опция)** | в контейнере брокера | в составе образа брокера; работает, только когда в «Размещении» подключён vCenter | в открытом UDS 5 поставщика VMware нет — написан заново: версия пула = полная копия эталона + снимок, столы — связанные, полные или мгновенные клоны, профиль NVIDIA vGPU на версию пула; MAC из диапазона UDS, размер vCPU/памяти, питание через VMware Tools, проверка сертификата vCenter |
| **Агенты узлов** | `vdi-hostagent` — на всех узлах; `vdi-certsync` — на фронтах; `vdi-nodeagent` — на туннелях, шлюзах и пограничных фронтах | ставит мастер (роли установки) или команда подключения узла из кабинета | нагрузка, службы и опись пакетов → «Состояние системы» и «Уязвимости»; сертификаты и правила фронтов из кабинета; роль, образы и VIP подключённых узлов |
| **Агент «Программы и настройки» (агент VDI)** | рабочие столы (Windows, Linux) | ставит команда подготовки образа; дальше обновляется сам из кабинета | программы, файлы настроек и сертификаты на столы по назначению из кабинета; профили пользователей в S3 |
| **Документация** | — | справка кабинета («Справка»); та же справка — в `docs/` репозитория выпусков | установка, руководство администратора, устройство, решение проблем, справочник |

## Как ставится и обновляется

- **Поставка:** пакет выпуска `cloududs-X.Y.Z.tar` на GitHub Releases репозитория выпусков: образы контейнеров, код ролей и мастера, агент UDS, клиенты сотрудников, подписанный манифест (Ed25519). `install.sh` проверяет подпись и контрольные суммы до распаковки.
- **Установка:** мастер на ВМ установщика создаёт ресурсы в проекте VK Cloud, ставит на узлы пакеты Ubuntu (Docker, MariaDB, HAProxy) и по SSH загружает образы из пакета — интернет для образов не нужен. Туннели, шлюзы HTML5 и узлы DMZ мастер подключает через кабинет одноразовыми кодами. Пошагово — [«Установка в VK Cloud»](deploy.md).
- **Обновление:** тем же мастером, по одному узлу; туннели, шлюзы и пограничные фронты обновляют свои агенты из кабинета; агент VDI на столах — сам; агент UDS — с новой версией образа стола. Подробно — [«Обновления»](updates.md) и UPGRADE.md в репозитории выпусков.
- **Опция VMware vSphere:** vSphere заказчик разворачивает сам (например, на VK Cloud Bare Metal as a Service); провайдер уже есть в брокере — после установки подключите vCenter в «Размещении», служебную учётную запись и права — по [«Учётные записи и права»](accounts.md).
