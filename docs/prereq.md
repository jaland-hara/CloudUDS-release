# Что нужно до установки

*Начало работы*

> Серверы и ресурсы по профилям инсталляции (для расчёта стоимости), сети и порты, DNS и сертификаты, учётные записи, особенности VK Cloud и опции vSphere.

## Серверы и ресурсы по профилям инсталляции

Все узлы — Ubuntu 24.04 LTS на дисках SSD. ВМ, сети, группы безопасности, порты VIP и плавающие IP создаёт мастер установки в проекте VK Cloud; он же проверяет размеры ВМ и берёт наименьший подходящий флейвор выбранного семейства. Образы контейнеров приходят из пакета выпуска с ВМ установщика — узлам нужен только доступ к зеркалу пакетов Ubuntu (или прокси для apt). Столы — сверх этого, по размеру пулов.

Что мастер создаёт в проекте VK Cloud для каждого профиля инсталляции — по этим таблицам считается стоимость серверной части в калькуляторе VK Cloud. Тип ВМ — наименьший флейвор выбранного семейства с не меньшими vCPU и RAM (по умолчанию STD3); если в семействе нет точного размера, фактические vCPU и RAM будут больше. Диски — загрузочные тома SSD (тип ceph-ssd по умолчанию, меняется в мастере). Точные цифры конкретной установки мастер показывает в плане на экране «Подготовка облака» до создания ресурсов.

Кроме ВМ: маршрутизатор с выходом в интернет (SNAT) — один, если мастер создаёт новый; порты VIP — по одному на пару фронтов и пару туннелей (стандартный и расширенный); бакеты S3 профилей пользователей и резервных копий — по объёму данных; ВМ установщика между обновлениями можно выключить — тогда платится только её диск. Столы считаются отдельно: размер ВМ стола (vCPU, RAM) × число столов в пулах, плюс диск каждого стола по размеру из пула.

## Сети и порты

Сети по слоям (в облаке — отдельные подсети, общий роутер): фронты, приложения (брокеры, кабинет, туннели, шлюзы), СУБД, корпоративная (контроллеры домена), столы; в расширенном профиле инсталляции — DMZ вне диапазона внутренних сетей.

| Откуда | Куда | Порт | Зачем |
|----|----|----|----|
| сотрудники (контур / VPN) | VIP фронтов | 443 | портал, кабинет, вход из браузера |
| сотрудники (контур / VPN) | VIP туннелей | 443 | клиент UDS |
| интернет | FIP пограничных фронтов / внешних туннелей | 443 | расширенный профиль |
| пограничные фронты | VIP фронтов | 8443 (PROXY), 443 | передача сеансов; агент узла |
| фронты | брокеры / кабинет / шлюзы HTML5 | 8000 / 8100 / 8080 | балансировка |
| брокеры и кабинет | Galera | 3306 (через локальный HAProxy) | база UDS и кабинета |
| узлы Galera между собой |  | 3306, 4444, 4567, 4568 | репликация |
| туннели и шлюзы | VIP фронтов | 443 | тикеты сеансов, регистрация, агенты |
| туннели и шлюзы | столы | 3389 | RDP |
| брокеры | столы | 43910 | агент UDS на столе |
| столы | портал (VIP фронтов) | 443 | регистрация агента UDS, агент «Программы и настройки» |
| столы, брокеры, кабинет | контроллеры домена | 636 (LDAPS), 53, 88, 389, 445… | вход, группы, ввод в домен, смена пароля |
| брокеры и кабинет | API VK Cloud (в опции vSphere — и vCenter) | 443 | создание столов, питание, сети |
| ВМ установщика | все узлы | 22 | установка и обновления по SSH (правило создаёт мастер) |
| бастион / администраторы | все серверы | 22 | обслуживание; узлы в DMZ — только с бастиона |

Группа безопасности столов: RDP 3389 — с туннелей и шлюзов (и из корпоративных сетей, если выбран вход «напрямую»); 43910 — с брокеров (агент UDS на столе: выход сотрудника, перезагрузка, снимок экрана).

## DNS и сертификаты

- **Внутренние имена** (DNS организации): портал → VIP фронтов, туннели → VIP туннелей. Подсеть столов раздаёт DNS контроллеров домена.
- **Сертификат портала** на внутреннее имя — от CA организации (AD CS); корень раздаётся компьютерам сотрудников групповой политикой, на столы его ставит команда подготовки образа, узлам — команда подключения.
- **Публичное имя** (расширенный профиль инсталляции): поддомен делегирован в публичный DNS VK Cloud (ns1/ns2.mcs.mail.ru) — это условие поставки в VK Cloud; DNS-балансировка (GSLB) включается для проекта по запросу в VK Cloud. Сертификат Let's Encrypt выпускает и продлевает кабинет.
- **Без внутреннего CA**: портал по IP фронтов без проверки сертификата — работает, но с рисками (подмена адреса в сети); подготовка образов предлагает оба варианта.

## Учётные записи

| Учётная запись | Где | Права | Нужна |
|----|----|----|----|
| сервисная учётка проекта для мастера | VK Cloud | «Администратор ВМ», «Администратор сети», «Администратор сетевой безопасности» (или «Администратор проекта») | установка и обновление: сети, группы безопасности, ВМ, FIP |
| сервисная учётка облака для столов (service-users) | VK Cloud | «Младший администратор ВМ» | всегда: столы, питание, порты VIP; можно ту же, что у мастера |
| учётка VK Cloud DNS | VK Cloud | «Администратор сети» (отдельной роли для DNS нет) | внешний вход и Let's Encrypt через VK DNS |
| чтение каталога | AD | чтение пользователей и групп | всегда с доменом |
| ввод столов в домен | AD | создание и удаление компьютеров в OU столов | если столы в домене |
| служебная учётка vCenter | vCenter | роль на папку и пул ресурсов CloudUDS | только в опции vSphere |
| бакеты профилей и резервных копий | S3 (Объектное хранилище VK Cloud) | свой аккаунт S3 у каждого бакета, доступ только к нему | профили сотрудников и резервные копии кабинета |
| почта | SMTP организации | отправка | уведомления, второй фактор по почте |

Минимальные права по каждой — [«Учётные записи и права»](accounts.md).

## Особенности VK Cloud

- Общий адрес пары (VIP) — порт в подсети и allowed address pairs на портах узлов; кабинет делает это сам учётной записью облака.
- FIP на свободном порту VIP не работает (Sprut): поэтому внешний вход — FIP на каждом пограничном узле и DNS-балансировка.
- Балансировщик облака (Octavia) живёт в одной зоне доступности — в схеме не используется; Anycast IP проверялся и отклонён.
- Galera — три узла в трёх зонах (ME1, MS1, PA2): потеря одной зоны не останавливает запись.
- Квоты проекта: ВМ, vCPU, RAM, диски, FIP — по таблицам «Серверы и ресурсы по профилям инсталляции» выше, плюс ВМ установщика и столы; сети и группы безопасности.
- Сети: мастер создаёт подсети фронтов, приложений, баз, DMZ и столов на одном маршрутизаторе с выходом в интернет (SNAT) — узлам нужны пакеты ОС, ВМ установщика — связь с узлами по SSH.
- Связь с организацией: контроллеры домена и сети пользователей должны быть доступны из проекта (VPN или прямое подключение).

## Опция: VMware vSphere на выделенных серверах

- Нужна, только если заказчику нужен свой vSphere (например, для NVIDIA vGPU). Серверы заказчик арендует в VK Cloud Bare Metal as a Service (или использует свои), ESXi и vCenter разворачивает и лицензирует сам; со стороны CloudUDS — только подключение к vCenter.
- vCenter доступен с брокеров по имени; брокеры проверяют его сертификат.
- Служебная учётка vCenter с ролью на папку и пул ресурсов CloudUDS; эталонные ВМ в этой папке.
- Сеть столов должна быть связана с сетями проекта VK Cloud: порт-группы приходят на ESXi VLAN-ами, столы в той же сети, что и облачные (туннели и шлюзы общие).
- Перенос эталона из vSphere в облако — deploy/tools/vsphere-to-vkcloud.sh (virt-v2v с драйверами virtio).

## Компьютеры сотрудников

- UDS Launcher для Windows, macOS, РЕД ОС, Astra, Альт — скачивается с портала; браузер — для входа «В браузере».
- Доверие сертификату портала (корень CA организации в системном хранилище).
- Из интернета: только 443 до портала и туннелей; VPN-приложения с подменой DNS мешают — для домена портала нужно правило DIRECT.
