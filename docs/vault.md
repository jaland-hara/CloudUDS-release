# Хранилища секретов и ключей

*Обслуживание*

> Копия секретов установки во внешнем хранилище — VK Cloud или своём (Vault, OpenBao, Stronghold, Barbican): для восстановления после аварии и хранения ключей у организации.

## Зачем

- Без внешнего хранилища секреты установки есть только на её узлах, на ВМ установщика и в резервной копии кабинета. Потеря проекта или ВМ установщика — и часть ключей не восстановить (ключи UDS, SSH-ключ к узлам).
- Хранилище держит **копию**: секреты живут в установке, кабинет и мастер установки дописывают их в хранилище при изменениях. При старте узлы из хранилища ничего не читают — его недоступность не останавливает работу.
- Можно подключить несколько хранилищ, например VK Cloud и Vault организации: каждое получает полную копию.

## Что копируется

| Запись | Что это | Кто пишет |
|----|----|----|
| `panel.master-key` | мастер-ключ кабинета: без него не расшифровать секреты в базе кабинета и в резервной копии | кабинет |
| `panel.uds-service-account`, `panel.db-password`, `panel.uds-db-readonly` | служебная учётная запись UDS кабинета, пароли кабинета к базам | кабинет |
| `panel.node-ca`, `certs.acme-account`, `certs.site-…` | CA узлов (mTLS), учётная запись ACME, действующие сертификаты сайта с ключами | кабинет |
| `panel.config` | конфигурация кабинета (без секретов) | кабинет |
| `installer.secrets` | секреты установки: ключи UDS (`UDS_SECRET_KEY`, `UDS_RSA_KEY`), пароли баз и ролей, пароль VRRP, корень сертификатов установки | мастер установки |
| `installer.ssh-key`, `installer.inventory` | SSH-ключ мастера к узлам; состав установки и параметры мастера | мастер установки |

Не копируется: закрытая половина ключа восстановления резервных копий (она только у администратора — так копии и ключ к ним хранятся раздельно), ключ портала у каждого узла (создаётся заново).

## Какие хранилища

| Хранилище | Секреты | Ключ для шифрования конвертом |
|----|----|----|
| VK Cloud — Менеджер секретов | в проекте VK Cloud, по каталогу `cloududs/<код>`; сервисная учётная запись с ролью «Менеджер секретов» | ключ шифрования ключей в Barbican того же проекта (Менеджер ключей VK пока не умеет шифровать через API) |
| OpenStack Barbican | VK Cloud key-manager или частное облако OpenStack | ключ шифрования ключей в том же Barbican |
| Vault API (KV v2) | HashiCorp Vault, OpenBao, Deckhouse Stronghold, Platform V Secrets Management и другие совместимые; вход AppRole или токеном, пространство имён, свой корень УЦ | Transit: ключ не покидает хранилище |

Шифрование конвертом: каждое значение шифруется своим ключом данных (AES-256-GCM), а тот — ключом из «ключницы». В хранилище секретов остаётся только шифротекст; для восстановления нужен доступ к обоим. Без конверта значения защищает само хранилище (его шифрование и права).

## Как подключить

1.  **«Хранилища секретов»** → «Подключить хранилище»: тип, адрес и учётная запись → «Проверить» (кабинет пробует запись, чтение и ключ) → «Сохранить» → «Синхронизировать».

2.  Или до установки: мастер установки, экран «Параметры» → «Внешнее хранилище секретов и ключей». Шаг установки «Секреты установки → внешние хранилища» передаст хранилище кабинету и запишет секреты мастера.

3.  Уже установленная система: после подключения в кабинете — в мастере «Параметры» → «Записать секреты сейчас» (или дождитесь следующего обновления: шаг «Секреты установки → внешние хранилища» есть и в нём).

4.  Vault / OpenBao: политика только на каталог установки. Пример для `cloududs/corp`:

    ``` bash
    path "secret/data/cloududs/corp/*"     { capabilities = ["create","update","read","delete"] }
    path "secret/metadata/cloududs/corp/*" { capabilities = ["create","update","read","delete","list"] }
    path "secret/metadata/cloududs/corp/"  { capabilities = ["list"] }
    path "transit/encrypt/cloududs-corp"   { capabilities = ["update"] }
    path "transit/decrypt/cloududs-corp"   { capabilities = ["update"] }
    ```

    Роль AppRole с этой политикой, `role_id` и `secret_id` — в кабинет. Ключ Transit создайте заранее (`bao write -f transit/keys/cloududs-corp`).

5.  Узлы кабинета должны достучаться до хранилища (порт 443 или 8200 до Vault; `msk.cloud.vk.ru`, `msk.cloud.vk.com` и Keystone `infra.mail.ru` — до VK Cloud).

## Как следить

- Кабинет синхронизирует каждые 6 часов и после «Синхронизировать»; раз в час сверяет контрольные суммы. Отставание или недоступность — в «Состоянии системы» (строка «Хранилище секретов …») и уведомление в канал «Безопасность».
- «Проверить восстановление» читает каждое значение обратно (с расшифровкой конверта) и сравнивает с кабинетом — делайте после подключения и раз в квартал.
- Учётные данные хранилищ хранятся в базе кабинета зашифрованными мастер-ключом и в браузер не возвращаются. Раздел видит Аудитор (без значений), меняет только Администратор.
- Значения в хранилище при отключении не удаляются — удалите каталог установки в самом хранилище, если он больше не нужен.

## Восстановление из хранилища

**Потеряна ВМ мастера установки.** Узлы и кабинет работают, но обновлять и чинить узлы нечем: секреты установки и ключ к узлам были только у мастера.

1.  Создайте ВМ мастера **с прежним внутренним адресом** (группы безопасности узлов пускают SSH только с него) и выполните `install.sh` той же версии.
2.  Первый экран мастера → «Восстановить из хранилища»: подключите то же хранилище, каталог — `cloududs/<код организации>`, «Сохранить хранилище».
3.  «Найти установку» — мастер прочитает и покажет, что записано: организация, профиль, версия, узлы. Ничего не меняется; суммы значений сверяются с записанными.
4.  «Восстановить» — секреты установки (`installer.secrets`), ключ к узлам (`installer.ssh-key`), состав установки, состояние шагов, корень установки и выпущенные им сертификаты (`installer.inventory`). Затем мастер проверяет, что каждый узел отвечает по SSH.

После этого мастер снова обновляет установку и повторяет шаги. Проверено на стенде: секреты, ключ и сертификаты совпали с исходными байт в байт, все 15 узлов ответили.

- Секреты мастера записываются шагом установки и обновления «Секреты установки → внешние хранилища» и кнопкой «Записать секреты сейчас» («Параметры»). Пока они не записаны, восстанавливать нечего.
- Кабинет: мастер-ключ (`panel.master-key`) нужен, чтобы восстановить базу кабинета из резервной копии ([«Резервные копии и восстановление»](backup.md)).
- Значения в конверте расшифровываются ключом из «ключницы» — сохраните доступ к ней вместе с доступом к хранилищу.

Как это устроено и защищено — [«Хранилища секретов и ключей: как устроено и как защищено»](vault-design.md).
