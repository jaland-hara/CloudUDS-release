# CloudUDS: функциональная карта

Версия документа: 0.1.0-rc.32, 07.10.2026.

CloudUDS — система виртуальных рабочих столов (VDI) в VK Cloud: система и столы работают в проекте VK Cloud заказчика. В её основе брокер OpenUDS 5.
Опция: заказчик может подключить свой VMware vSphere — например, развернуть его сам на выделенных серверах VK Cloud Bare Metal as a Service со своими лицензиями VMware (обычно ради NVIDIA vGPU).
Поверх брокера CloudUDS добавляет:
- установщик;
- кабинет администратора;
- портал сотрудников;
- агенты на узлах и рабочих столах;
- доработанный клиент UDS;
- отказоустойчивый контур с входом из интернета.

Документ перечисляет возможности по областям и сравнивает их со штатным OpenUDS 5. Отметки в таблицах:
- **CloudUDS** — возможности нет в штатном OpenUDS 5, она добавлена в CloudUDS;
- **доработано** — возможность есть в OpenUDS, CloudUDS её расширяет или упрощает;
- **OpenUDS** — штатная возможность брокера, доступна без изменений.

## 1. Развёртывание и жизненный цикл

| Функция | Что даёт | Отметка |
|---|---|---|
| Веб-мастер установки | Ставит систему в проект VK Cloud заказчика. Создаёт сети, группы безопасности, порты VIP, диски и ВМ, затем настраивает узлы по SSH. Шаги повторяемы: после ошибки установка продолжается с упавшего шага | CloudUDS |
| Профили установки | Минимальный (1 ВМ, пилот до ~50 столов), базовый (7 ВМ, по ВМ на роль), стандартный (11 ВМ, отказоустойчивый в трёх зонах), расширенный (15 ВМ, плюс вход из интернета через DMZ) | CloudUDS |
| Предпроверка | Перед установкой мастер проверяет ресурсы узлов, время, DNS и зеркало пакетов. Каждую связь между ролями он проверяет настоящим TCP-подключением | CloudUDS |
| Подписанные выпуски | Пакет выпуска содержит образы всех контейнеров и подписан Ed25519. Подпись и контрольные суммы проверяются до распаковки. Узлам не нужен доступ к реестрам образов в интернете | CloudUDS |
| Обновление без остановки | Узлы обновляются по одному: брокеры, кабинет, фронты, Galera, туннели и шлюзы. Сеансы в туннелях не рвутся. Перед обновлением мастер требует резервную копию и зелёное «Состояние системы» | CloudUDS |
| Обновление ОС узлов | Узлы обновляются по одному с перезагрузкой и проверкой роли после каждого. Обновления безопасности Ubuntu ставятся автоматически | CloudUDS |
| Резервное копирование | Базы UDS и кабинета, конфигурация и секреты копируются в S3 по расписанию и вручную. Копии зашифрованы ключом восстановления, который есть только у администратора. Целостность копий проверяется. Восстановление выполняется инструментом `vdi-restore` | CloudUDS |

## 2. Где работают рабочие столы

| Функция | Что даёт | Отметка |
|---|---|---|
| VK Cloud (OpenStack) | Столы создаются из образов и томов облака. Кабинет выбирает тома по ID, тип и зону диска, сеть и группу безопасности из списка проекта. Диски столов получают имя стола, поэтому их легко найти в консоли облака | доработано |
| Несколько проектов VK Cloud | Столы можно размещать в нескольких проектах облака одной установки (в опции vSphere — и в нескольких vCenter) | CloudUDS |
| VMware vSphere (опция) | Для заказчиков, которые сами развернули vSphere — например, на выделенных серверах VK Cloud Bare Metal as a Service. Собственный поставщик для UDS: связанные, полные и мгновенные клоны, питание, хранилища и порт-группы, проверка vCenter. В открытом OpenUDS 5 поставщика VMware нет | CloudUDS |
| NVIDIA vGPU (опция vSphere) | Столы с видеокартой в vSphere заказчика: профили vGPU, выбор в мастере пула. Готовая команда настройки графики RDP для эталона с vGPU («Образы» → «Столы с vGPU»): AVC444, кодирование на видеокарте, 60 или 30 кадров/с; на ВМ без NVIDIA ничего не меняет. 4K-видео на T4-8Q — 60–75 кадров/с вместо ~30. Подробно: [Столы с vGPU: настройка](vgpu.md) | CloudUDS |
| Другие поставщики: Proxmox, oVirt, OpenNebula, Xen, статические машины | Есть в брокере, но кабинет их не настраивает. Доступны через штатную админку UDS | OpenUDS |

## 3. Образы, пулы и столы

| Функция | Что даёт | Отметка |
|---|---|---|
| Каталог образов | Образы ОС, из которых администратор создаёт пулы, можно править в кабинете. Есть сборка своего образа и подготовка эталона: агент UDS ставится автоматически | CloudUDS |
| Мастер пула | Одна форма вместо 6–8 объектов UDS (поставщик, сервис, менеджер ОС, транспорты, пул, публикация, группы). В ней можно выбрать только совместимые сочетания образа, диска, сети, политики и режима входа | доработано |
| Вход доменной или локальной учёткой | Режим входа объяснён словами. Сменить его можно через пул-двойник: в штатном UDS смена на работающем пуле молча не применяется | доработано |
| Мета-пулы | Один значок у сотрудника, несколько пулов за ним. Готовые сценарии «по очереди», «поровну», «где свободнее». Есть прогноз выдачи, запасной пул в один клик и вывод пула из выдачи | доработано |
| Календари и экономия | Рабочие часы, ночи, праздники, окна обслуживания. Простаивающие столы выключаются и сами включаются при следующем подключении | доработано |
| Конфигурации и запросы ресурсов | Наборы vCPU, памяти и диска. Сотрудник просит больше ресурсов, администратор одобряет, кабинет применяет к столу | CloudUDS |
| Программы и настройки | Доставка на столы программ, файлов настроек и сертификатов. Есть автономные пакеты для собственных средств распространения организации (SCCM, GPO, Ansible) | CloudUDS |
| Профили пользователей в S3 | Профиль сотрудника сохраняется в S3 и возвращается на любой стол пула. На столах нет ключей S3: агент получает временные подписанные ссылки | CloudUDS |
| Агенты на столах | Агент UDS собран с доработками: пароль локальной учётки, сборка для Astra Linux. Свой агент «Программы и настройки» для Windows и Linux ставит программы, файлы, сертификаты и переносит профили; он обновляется сам. Для мгновенных клонов vSphere есть отдельный скрипт подготовки | доработано |
| Столы Linux | Образы RED OS, Astra Linux, ALT с xrdp. Масштабирование для экранов высокой чёткости | CloudUDS |
| Несколько мониторов | Сеанс на все мониторы сотрудника с клиентом CloudUDS: окно на весь экран на каждом мониторе, переключение «все экраны / один экран» на ходу | CloudUDS |

## 4. Сотрудники и доступ

| Функция | Что даёт | Отметка |
|---|---|---|
| Каталог пользователей | Active Directory, Samba AD, FreeIPA / ALD Pro, OpenLDAP — проверены по два сервера, с переключением при отказе. Вход как `user@domain` или `DOMAIN\user` | доработано |
| LDAPS / StartTLS | Шифрованная связь с каталогом, доверенные центры сертификации задаются в кабинете | доработано |
| Вход на стол без пароля после ADFS | Сотрудник вошёл на портал через ADFS — Windows не спрашивает пароль ещё раз. Брокер выпускает короткий сертификат входа по смарт-карте через AD CS домена, клиент CloudUDS входит по Kerberos PKINIT. Встроенный KDC Proxy на каждом узле портала: контроллер домена наружу не открывается. Проверка всей цепочки одной кнопкой. Как VMware True SSO и Citrix FAS | CloudUDS |
| Единый вход ADFS / SAML 2.0 | Подключение по метаданным ADFS, проверка настроек, готовые команды PowerShell для администратора ADFS, смена ключа SP без перерыва во входе. Вход через ADFS и вход по паролю домена — одна учётная запись. Есть глобальный выход | доработано |
| Второй фактор для сотрудников | TOTP, e-mail, SMS через HTTP-шлюз, RADIUS OTP. Готовые SMS-шлюзы, доверенные сети, тестовая отправка | доработано |
| Политики подключения | Именованные наборы: перенаправление устройств (диски, буфер обмена, принтеры, микрофон, камера, смарт-карты), качество изображения, экономия. Одна правка применяется ко всем пулам с этой политикой | доработано |
| Права на пулы | Пул выдаётся группе каталога; сеть по умолчанию задаётся для группы пользователей | доработано |

## 5. Портал сотрудника

| Функция | Что даёт | Отметка |
|---|---|---|
| «Мои рабочие столы» | Список своих столов с состоянием. Подключение «в браузере» или «через приложение», без технических названий транспортов | доработано |
| Перезагрузка и чистый стол | «Перезагрузить стол» — если стол завис (включено в новых пулах по умолчанию). «Получить чистый стол» (или «Удалить стол и получить новый» для постоянных столов) — администратор разрешает в пуле. Оба действия с подтверждением | OpenUDS |
| Заявки | Запросы на стол, программу и ресурсы, которые разбирает администратор в кабинете | CloudUDS |
| Смена пароля | В том числе пароля AD (нужен LDAPS на контроллере домена) | CloudUDS |
| Клиенты для скачивания | Клиент CloudUDS для Windows, macOS, RED OS, Astra Linux, ALT поставляется в выпуске и скачивается с портала | CloudUDS |
| Изоляция | Портал работает в отдельном контейнере без мастер-ключа и без учётной записи UDS. Каталог столов он читает из витрины, которую публикует кабинет | CloudUDS |
| Штатный портал UDS | Остаётся доступен по ссылке с `?classic=1` | OpenUDS |

## 6. Подключение к столу

### Клиент CloudUDS 5.0.1

| Функция | Что даёт | Отметка |
|---|---|---|
| Панель сеанса | Язычок у верхнего края открывает панель по клику и не мешает строке меню macOS; положение запоминается. Кнопки с подписями: «Закрепить», «Ctrl+Alt+Del», «Все экраны / Один экран», «Настройки», «Переподключить», «Свернуть», «Окно / Полный экран», «Отключиться». Ctrl+Alt+Home открывает панель с клавиатуры | CloudUDS |
| Устройства на лету | Буфер обмена, диски, микрофон и камера включаются и выключаются во время сеанса, без переподключения. Выключенная камера освобождается. Пользователь может только сузить то, что разрешил администратор | CloudUDS |
| «Переподключить» | За 2–3 секунды подключается к тому же сеансу Windows, программы остаются открытыми. Так применяются цветность и качество. Если стол не принял новые настройки, клиент сам возвращает прежние | CloudUDS |
| H.264 / AVC444 | Видео и 4K без зависаний. На Mac — аппаратное декодирование (VideoToolbox): обработка кадра 4K ~6 мс вместо 75 | доработано |
| Качество «Авто» | Клиент следит за каналом по замерам самого Windows (задержка, полоса). На медленном канале стол переходит на пониженное разрешение, на хорошем возвращается полное — без переподключения | CloudUDS |
| «Экономия» | Стол рисует вдвое меньше пикселей по каждой стороне, клиент растягивает картинку: поток в ~4 раза меньше, микрофон сжимается. Для мобильных и перегруженных каналов | CloudUDS |
| Метрики связи | Alt+F (на Mac ⌥+F) в окне сеанса: кадры/с, кодек, поток, время декодирования, задержка и полоса канала | CloudUDS |
| Звук и камера | Адаптивный буфер воспроизведения (без заиканий на тяжёлом видео), AAC для звука стола, чистый микрофон, встроенная камера Mac 720p | доработано |
| Вход без пароля | Клиент несёт Kerberos с PKINIT и HTTPS до KDC Proxy (на Windows — MIT krb5, доверие по системному хранилищу сертификатов) | CloudUDS |
| Устойчивость к сети | Сначала туннель в TLS, затем обычный. Перебор адресов брокера и туннелей с короткими таймаутами, запоминание узла, который ответил. Отчёт о недоступных адресах уходит администратору | CloudUDS |
| Сообщения об ошибках | Потеря соединения показывается окном с причиной, клиент не закрывается молча | доработано |

### Пути подключения

| Функция | Что даёт | Отметка |
|---|---|---|
| Клиент UDS через туннель | RDP до стола внутри контура, снаружи открыт только порт 443 | OpenUDS |
| Браузер (HTML5) | Guacamole без установки клиента; шлюзы HTML5 — пара узлов с балансировкой | доработано |
| Гибридные туннели | Одни и те же серверы туннелей для сотрудников в интернете и в корпоративной сети | CloudUDS |
| Вход из интернета | Пограничные фронты и внешние туннели в DMZ с плавающими IP. Публичные имена с балансировкой VK DNS (GSLB). TLS сотрудника расшифровывается только на внутренних фронтах | CloudUDS |
| Туннель внутри TLS | Туннель UDS v5 принимает TLS 1.3 на том же порту и снаружи выглядит как HTTPS. Помогает, когда провайдер блокирует незнакомые протоколы | CloudUDS |
| Длинные каналы с потерями | TCP BBR на фронтах и узлах туннеля: на дальнем канале с потерями поток вырос с ~2,5 до ~65 Мбит/с, 4K-видео — с 11–20 до 40–49 кадров/с | CloudUDS |
| Собственные имена узлов | У каждого фронта и туннеля своё DNS-имя. Клиент получает список узлов и обходит заблокированные адреса | CloudUDS |
| X2Go, SPICE, HTML5 SSH/VNC | Есть в брокере, кабинет их не настраивает | OpenUDS |

| Уведомления | E-mail (SMTP) и Telegram, подписка на события по каналам: отказ и восстановление компонентов, сертификаты, внешний вход, заявки | CloudUDS |
| Журнал и аудит | Кто, куда, откуда и как подключался, с городом и страной по адресу. Аудит входов и действий администраторов. События UDS. Передача в SIEM по syslog TLS или HTTPS | CloudUDS |
| Уязвимости | Опись пакетов и образов узлов, проверка по базе OSV.dev | CloudUDS |

| Размещение | Подключение проектов облака, туннелей и шлюзов HTML5 одноразовым кодом (в опции vSphere — и vCenter): токены узлов людям не выдаются. VIP групп туннелей кабинет держит сам | CloudUDS |
| Администраторы | Роли, второй фактор TOTP для входа в кабинет, восстановление доступа с сервера | доработано |
| Справка | Дерево разделов, статья на страницу с оглавлением, поиск, ссылки на статьи, кнопка «?» на каждом экране кабинета. Та же справка опубликована как документация в репозитории выпусков | CloudUDS |
| Штатная админка UDS | Остаётся доступна для того, чего нет в кабинете: уведомители UDS, отчёты, конфигурация брокера, разбор логов сервисов | OpenUDS |

## 8. Безопасность

| Функция | Что даёт | Отметка |
|---|---|---|
| Защита входа | Лимит попыток с адреса на фронтах, блокировка адресов, своя капча без внешних сервисов. Кабинет можно закрыть для интернета | CloudUDS |
| Белые списки адресов | Отдельные списки сетей для кабинета и портала сотрудников, применяются на фронтах. Кабинет не даст сохранить список, который отрежет текущего администратора; при потере доступа — восстановление командами на узле кабинета | CloudUDS |
| mTLS узлов | Туннели и шлюзы подтверждают себя сертификатом узла. Закрытый ключ создаётся на узле и его не покидает. Есть список отзыва | CloudUDS |
| Токены, привязанные к адресу | Брокер принимает токен туннеля или шлюза только с адреса этого узла | CloudUDS |
| Шифрование СУБД | TLS для всех соединений с MariaDB и репликации Galera, шифрование данных на диске | CloudUDS |
| Секреты | Секреты кабинета зашифрованы мастер-ключом (AES-256-GCM); мастер-ключ в базу не попадает. Пароли и ключи не возвращаются в браузер | CloudUDS |
| Ограниченные контейнеры | Без привилегий ядра, без повышения прав, корневая файловая система только для чтения, лимит процессов | CloudUDS |

## 9. Сравнение со штатным OpenUDS 5

| Область | Штатный OpenUDS 5 | CloudUDS |
|---|---|---|
| Установка | Пакеты и контейнеры ставятся вручную, отказоустойчивость собирается самостоятельно | Мастер, четыре профиля, отказоустойчивый контур в трёх зонах, подписанные выпуски, обновление по узлам |
| Администрирование | Конструктор объектов брокера: согласованность объектов — забота администратора | Сценарии на русском языке: «дать группе стол», «сменить образ», «кто на каком столе», «что сломалось» |
| Платформы | OpenStack, Proxmox, oVirt, OpenNebula, Xen, статические машины; VMware — нет | VK Cloud (с образами, томами, сетями); опция — VMware vSphere заказчика (клоны, vGPU); остальные — через штатную админку |
| Протоколы | RDP, HTML5 (RDP, VNC, SSH), X2Go, SPICE | RDP через клиент CloudUDS и HTML5 в браузере; остальные — через штатную админку |

## 10. Ограничения версии 0.1.0-rc.32

- Ручной режим установки (на ВМ, созданные администратором) не готов.
- Вход на стол без пароля после ADFS проверен в клиентах для Windows и macOS. Клиенты для Linux собраны с той же поддержкой, но ещё не проверены. В браузере (HTML5) Windows спрашивает пароль.
- RDP-UDP через туннель выключен: через ретранслятор UDS стандартные клиенты Microsoft зависали. Все подключения идут по TCP (с BBR).
- Выключить на лету можно только диски, которые перенаправляются как «все диски». Диски из явного списка путей выключаются со следующего подключения.
- Без vGPU столы рассчитаны на офисную работу. 3D и CAD требуют vGPU. Столы в общем публичном облаке зависят от соседей по хосту, поэтому скорость графики и звука на них не гарантирована. Подробно — [Столы без видеокарты](nogpu.md).
- Продление сертификатов СУБД и внутреннего имени выполняется повтором шагов мастера.
