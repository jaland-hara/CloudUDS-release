# Базы данных

*Справочник*

> Какие СУБД и базы использует система, кто в них пишет, что штатное от OpenUDS и что добавлено нами.

## СУБД

| Что | Где и как |
|----|----|
| **MariaDB 10.11 + Galera 4** | Кластер из трёх узлов БД, по одному в зоне (роль `db`), синхронная репликация, догон узла — IST, полная перекачка — mariabackup. Штатная СУБД OpenUDS; Galera и роль — наши. Подъём после полного останова — `deploy/tools/galera-recover.sh`. |
| **Доступ брокеров** | В стеке брокера локальный HAProxy: пишет в один узел Galera, остальные — резерв; проверка «узел в Synced» на порту 9200. Так нет конфликтов записи между узлами. |
| **Доступ кабинета** | Своя учётная запись и своя база; база UDS — только чтение отдельной учётной записью. |
| **memcached** | В стеке брокера: кеш UDS, не база — теряется без последствий. |
| **SQLite** | Только в минимальной установке без кластера: база кабинета — файл на узле панели. |
| **PostgreSQL + Patroni** | Испытан как альтернатива Galera (UDS работает), в поставку не входит: у Galera переключение при отказе узла ~0,5 с против ~30 с. |

## Базы и кто в них пишет

| База | Чья | Кто пишет | Кто читает |
|----|----|----|----|
| **`dbuds`** | штатная OpenUDS | брокеры (веб и фоновые задачи) учётной записью `dbuds` | кабинет — учётной записью `vdipanel_ro` (только SELECT): журнал подключений, сеансы. Изменения кабинет делает только через REST UDS, напрямую в базу UDS не пишет. |
| **`vdipanel`** | наша | узлы панели учётной записью `vdipanel` | только кабинет |

## База UDS: что внутри и что изменено

Схема — штатная, создаётся миграциями OpenUDS 5 при первом запуске брокера. Там пулы и сервисы, провайдеры (облако, vSphere), транспорты, сети, назначения столов сотрудникам, пользователи и группы, аутентификаторы, второй фактор, туннели и серверы, календари, журналы, статистика, фоновые задачи, конфигурация UDS.

**Схему мы не меняем.** Все наши патчи брокера меняют код, а не таблицы. Данные, которые они добавляют, лежат в штатных полях:

- `tunnel-token-bind` — адрес, с которого принимается токен туннеля (`allowed_ip`), и время последнего обращения — в штатных свойствах регистрации сервера.
- Остальные патчи (вход по LDAP, несколько контроллеров, LDAPS, ввод в домен, имена томов OpenStack, повтор тикета, мультимонитор, TOTP по UTC, остановка стола, клиенты) данных в базу не добавляют.
- Объекты, которые создаёт кабинет (пулы, транспорты, группы туннелей, копии транспортов для корпоративной сети), — обычные объекты UDS; связи между ними кабинет хранит у себя (например, пары транспортов) — в тег UDS идентификатор не помещается.

## База кабинета: таблицы

Таблицы создаёт сам кабинет при запуске (CREATE TABLE IF NOT EXISTS), новые столбцы добавляются так же — отдельных миграций нет.

| Область | Таблицы | Что хранят |
|----|----|----|
| **Администраторы и вход** | `admins, admin_meta, panel_sessions, auth_fail, auth_notice` | кто администратор, второй фактор администраторов (секрет зашифрован), сессии кабинета, счётчики неверных паролей |
| **Организация и настройки** | `org_settings, integration_settings, integrations` | название, часовой пояс, адрес портала; подключения к облаку и vCenter (без паролей — они в UDS); прочие настройки: VIP групп туннелей, mTLS узлов, внешний вход, копирование |
| **Журнал и уведомления** | `audit, audit_meta, notify_channels, notify_log` | аудит действий (и очередь в SIEM), каналы уведомлений, история отправок |
| **Состояние системы** | `hosts, host_hist, health_alerts, panel_leader, panel_nodes` | агенты нагрузки узлов и история метрик, открытые сбои, какой узел панели ведущий, пульс узлов панели |
| **Образы и пулы** | `images, prep_keys, policies, group_placement, pool_cleanup` | карточки образов (эталоны), ключи скриптов подготовки, политики подключения, сеть групп, незавершённые удаления пулов |
| **Работа с сотрудниками** | `requests, exceptions, orphans, power_log, user_contacts` | запросы сотрудников и решения, исключения из экономии, сотрудники без доступа к столу, журнал включений и выключений, контакты для второго фактора |
| **Программы на столах** | `app_items, app_assign, app_agents, app_status, app_meta` | библиотека программ и файлов, назначения, агенты на столах, результаты установки |
| **Профили** | `profile_pools, profile_snapshots, profile_blobs, profile_events, profile_restores` | режим профилей по пулам, снимки и учёт файлов в S3 (сами файлы — в S3), события и восстановления |
| **Узлы и сертификаты** | `tunnel_joins, tunnel_jobs, node_agents, node_certs, front_certs, front_nodes, cert_jobs` | коды подключения узлов, установки по SSH, агенты узлов, сертификаты узлов (mTLS), сертификаты сайта (ключи зашифрованы), фронты, выпуск Let’s Encrypt |
| **Резервное копирование** | `backups` | история копий: когда, размер, контрольная сумма, проверка |

**Резервные копии**Обе базы целиком входят в ежедневную копию в S3 вместе с мастер-ключом и конфигурацией кабинета («Резервное копирование»). Восстанавливаются по отдельности: только база UDS, только база кабинета — или вся установка.
