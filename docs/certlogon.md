# Вход на стол без пароля (ADFS + сертификат)

*Руководство администратора → Безопасность · обновлено 06.10.2026*

> После входа на портал через ADFS стол не спрашивает пароль ещё раз: клиент входит в Windows сертификатом смарт-карты.

## Когда это нужно

При входе на портал через ADFS у CloudUDS нет пароля сотрудника, поэтому Windows спрашивает его ещё раз. Вход по сертификату убирает этот шаг. Так же работают VMware Horizon True SSO и Citrix FAS.

## Как это работает

1.  Сотрудник входит на портал через ADFS. CloudUDS знает его UPN, но не пароль.
2.  При запуске стола брокер просит ваш центр сертификации (AD CS) выпустить короткоживущий сертификат «вход со смарт-картой» от имени сотрудника.
3.  Клиент CloudUDS поднимает из сертификата программную смарт-карту и входит на стол по Kerberos PKINIT.
4.  Контроллер домена проверяет сертификат. Если клиент снаружи, Kerberos идёт через встроенный KDC Proxy фронтов.

> **Где работает.**
>
> Клиент CloudUDS для Windows и macOS. Клиенты для Linux собраны с той же поддержкой, но ещё не проверены. В браузере (HTML5) стол спрашивает пароль.

## Настройка

1.  В домене: шаблон сертификата «вход со смарт-картой», агент регистрации (Enrollment Agent) и учётная запись для выпуска.
2.  В кабинете: раздел **«Вход без пароля»** — центр сертификации, учётная запись, KDC Proxy.
3.  Кнопка **«Проверить настройку»** проверяет всю цепочку: выпуск сертификата, доступность KDC через прокси, доверие корню.

Подробно для администратора домена — docs/ops/cert-logon.md в поставке.
