# Учётные записи и права

*Справочник*

> Служебные учётные записи в домене, облаке и vCenter и их минимальные права.

## Кратко

| Учётная запись | Где указывается | Для чего | Минимальные права |
|----|----|----|----|
| **Каталог (чтение и группы доступа)** | «Пользователи» → «Домен организации» → «Учётная запись для чтения каталога» | вход сотрудников в UDS, поиск групп, персональный доступ к пулам (группы в OU=VDI), проверка сотрудников при отключении | обычный пользователь домена + в OU=VDI: создание и удаление групп, изменение их состава |
| **Ввод столов в домен** | «Пользователи» → «Ввод столов в домен» | ввод рабочих столов Windows и Linux в домен, удаление учётной записи компьютера при удалении стола | обычный пользователь домена + в OU для компьютеров столов: создание и удаление компьютеров и запись их служебных атрибутов |
| **Сотрудник (смена пароля)** | — | смена собственного пароля на портале | служебных прав не нужно: пароль меняет сам сотрудник своей учётной записью по защищённому каналу |
| **Сервисный пользователь облака** | настройки поставщика облака в UDS (кабинет использует её же) | создание и удаление столов, дисков и снимков, включение и выключение ВМ, чтение сетей и квот | роль «Младший администратор ВМ» только в проекте рабочих столов |
| **Служебная учётная запись vCenter (если есть пулы в vSphere)** | «Размещение» → «VMware vSphere» (хранится в провайдере UDS) | копии эталона и связанные клоны, снимки, питание, удаление столов, чтение хранилищ и порт-групп | роль с правами на ВМ, снимки, хранилища и сеть на датацентре + запрет доступа (NoAccess) на всё, что не принадлежит арендатору |

Проверено 28.09.2026: временным учётным записям выданы права по этой странице, все операции системы выполнены, операции за пределами выданных прав отклонены.

## 1. Учётная запись каталога (svc-vdi-ldap)

Создаётся как **обычный пользователь домена** (только группа «Пользователи домена»), без прав администратора. Чтения пользователей и групп хватает по умолчанию: в AD их может читать любой пользователь домена.

Для персонального доступа кабинет ведёт группы вида VDI-…-P03 в подразделении OU=VDI. Создайте OU заранее (иначе кабинету понадобилось бы право создавать OU в корне домена) и делегируйте права только на него:

dsacls "OU=VDI,DC=company,DC=local" /G "COMPANY\svc-vdi-ldap:CCDC;group"\
dsacls "OU=VDI,DC=company,DC=local" /I:S /G "COMPANY\svc-vdi-ldap:WP;member;group"

Первая строка — создание и удаление групп в OU=VDI, вторая — изменение состава этих групп. В выводе dsacls вторая строка отображается как «Add/Remove self as member» — это особенность вывода, право действительно позволяет добавлять в группу других.

**Не нужно:** «Администраторы домена», «Операторы учёта», права на пользователей, запись вне OU=VDI.

**Рекомендуется:** длинный случайный пароль с плановой сменой; запрет интерактивного входа и входа по RDP (групповая политика «Запретить локальный вход» и «Запретить вход через службу удалённых рабочих столов»); флажок «Учётная запись важна и не может быть делегирована»; подключение к каталогу по LDAPS с проверкой сертификата — иначе пароль этой учётной записи и пароли сотрудников идут по сети открыто.

**FreeIPA, ALD Pro, другой LDAP:** системная учётная запись с правом чтения пользователей и групп (в FreeIPA — в cn=sysaccounts,cn=etc). Группы персонального доступа кабинет ведёт только в AD; в других каталогах создавайте группы доступа средствами каталога.

## 2. Учётная запись ввода в домен (svc-vdi-join)

Создаётся как **обычный пользователь домена**. Для компьютеров рабочих столов заведите отдельное подразделение, например OU=VDI-Computers, и укажите его в поле «Подразделение (OU) для компьютеров» — без него столы попадают в CN=Computers, куда этой учётной записи доступа нет. Делегирование:

set OU="OU=VDI-Computers,DC=company,DC=local"\
set A=COMPANY\svc-vdi-join\
dsacls %OU% /G "%A%:CCDC;computer"\
dsacls %OU% /I:S /G "%A%:CA;Reset Password;computer"\
dsacls %OU% /I:S /G "%A%:RPWP;userAccountControl;computer"\
dsacls %OU% /I:S /G "%A%:WS;Validated write to DNS host name;computer"\
dsacls %OU% /I:S /G "%A%:WS;Validated write to service principal name;computer"\
dsacls %OU% /I:S /G "%A%:DT;;computer"\
rem для Linux-столов (samba net ads join):\
for %a in (operatingSystem operatingSystemVersion operatingSystemServicePack operatingSystemHotfix msDS-SupportedEncryptionTypes) do dsacls %OU% /I:S /G "%A%:WP;%a;computer"

- создание и удаление объектов «Компьютер» в этом OU — ввод стола и удаление его учётной записи при удалении стола (UDS делает это сам)
- сброс пароля компьютера, запись userAccountControl, проверенная запись DNS-имени и SPN — то, что происходит при вводе в домен
- атрибуты operatingSystem\* и msDS-SupportedEncryptionTypes — их записывает samba при вводе Linux-столов; для одних Windows не нужны
- если заполнено поле «Группа AD для компьютеров столов» — дополнительно право менять состав этой группы: dsacls "CN=VDI-Computers,…" /G "%A%:WP;member"

**Не нужно:** «Администраторы домена» и право «Добавление рабочих станций к домену» — учётная запись создаёт компьютеры по делегированию, а не по квоте. Хорошая практика для домена в целом — запретить обычным пользователям заводить компьютеры: ms-DS-MachineAccountQuota = 0.

**Учтите:** UDS подключается к контроллеру для удаления компьютеров своим отдельным подключением; включите для него LDAPS, чтобы пароль этой учётной записи не шёл по сети открыто.

## 3. Сотрудники и администраторы

- **Смена пароля на портале** выполняется учётной записью самого сотрудника: служебных прав не нужно. Условия — защищённое подключение к каталогу (LDAPS или StartTLS), не установлен флажок «Запретить смену пароля пользователем», соблюдена политика паролей домена (в том числе минимальный срок действия пароля).
- **Администраторы кабинета из домена** не получают прав в AD: кабинет отмечает их только внутри UDS. Для управления группами кабинет использует учётную запись каталога.

## 4. Облако VK Cloud: сервисный пользователь

UDS создаёт и удаляет рабочие столы от имени сервисного пользователя облака, указанного в настройках поставщика; кабинет использует его же (образы, питание столов, чтение сетей и квот). Операции:

- ВМ: создание из снимка, удаление, включение, выключение, перезагрузка, приостановка
- диски: создание, клонирование, смена типа, удаление; снимки дисков: создание и удаление; выгрузка диска в образ и удаление образа
- чтение: типы ВМ, зоны доступности, сети, подсети, порты, группы безопасности, квоты; подключение ВМ к сети и назначение ей существующей группы безопасности

| Роль | Подходит? | Почему |
|----|----|----|
| **Младший администратор ВМ (mcs_admin_vm_junior)** | рекомендуется, проверено | ВМ, диски, снимки и сети — без права менять группы безопасности (система их не создаёт, а только назначает готовые; их заводит сетевой администратор). Не может создавать образы Glance — см. ниже. |
| **Администратор ВМ (mcs_admin_vm)** | если нужно | то же плюс управление группами безопасности — только если их будет вести сама система или нужен перенос дисков-источников между зонами |
| **Оператор ВМ (mcs_operator_vm)** | мало | только запуск и остановка уже созданных ВМ — создавать столы не сможет |
| **Администратор проекта, Суперадминистратор, Владелец** | лишнее | полный доступ ко всем сервисам проекта; не выдавать |

**Проверено 29.09.2026** сервисным пользователем только с ролью «Младший администратор ВМ»: чтение типов ВМ, зон, сетей, подсетей, портов, групп безопасности, дисков, образов и квот; диск, пометка загрузочным, снимок; ВМ из снимка в сети столов с существующей группой безопасности, выключение, включение, перезагрузка, удаление; копия диска, смена типа, диск из образа Glance; удаление всего созданного — всё работает. Создать группу безопасности — запрещено (как и нужно).

**Ограничение:** этой роли нельзя создавать образы Glance. Кабинету это нужно только в одном случае — когда диск-источник для нового образа лежит в другой зоне доступности (VK Cloud копирует диски только внутри зоны, и кабинет переносит диск через временный образ). Тогда кабинет покажет понятную ошибку: скопируйте источник в зону столов или на время выдайте «Администратор ВМ».

**Рекомендуется:** отдельный проект для рабочих столов; сервисный пользователь только в нём; без доступа к биллингу и управлению участниками (IAM).

Роли и их состав — в документации VK Cloud: «Cloud Servers → Управление доступом».

## 5. VMware vSphere: служебная учётная запись vCenter (svc-uds-tNN)

Нужна, только если у организации есть пулы в vSphere. Создаётся в единой точке входа vCenter (vsphere.local) по одной на арендатора и указывается в провайдере «VMware vSphere» в UDS. Операции:

- копия эталонной ВМ (версия пула), связанные клоны от её снимка, создание снимков, удаление ВМ
- включение, выключение, перезагрузка, мягкое выключение через VMware Tools; смена MAC, порт-группы, числа vCPU и памяти при клонировании
- чтение: ВМ, папки, пулы ресурсов, хранилища (свободное место), порт-группы

**Роль** (например UDS-LinkedClone): права групп «Виртуальная машина» (инвентарь, конфигурация, взаимодействие, выдача, снимки), «Папка», «Хранилище» (выделение места, просмотр, файлы), «Ресурсы» (назначение ВМ в пул ресурсов), «Сеть» (назначение сети). Назначается на датацентр с наследованием и на корень без наследования.

**Запрет доступа (NoAccess)** той же учётной записи — на всё чужое: папки и пулы ресурсов других арендаторов и служебных ВМ, служебные ВМ (vCenter, шлюзы), порт-группы управления и других арендаторов, загрузочные хранилища серверов. Без этого при общих хранилищах и датацентре учётная запись увидит чужие ВМ.

Роль и права можно выдать скриптом (pyVmomi) — пример в исходниках, каталог deploy/vsphere.

**Проверено 28.09.2026:** учётная запись видит только эталон, хранилища и порт-группы своего арендатора; создание версии пула, связанных клонов, питание и удаление — работают. Найденная и исправленная ошибка изоляции: ВМ другого арендатора в общем пуле ресурсов были видны — каждую ВМ арендатора держите в его пуле ресурсов.

**Рекомендуется:** vCenter доступен брокеру только через шлюз арендатора; сертификат vCenter проверяется (корневой сертификат VMCA загружается в провайдер); пароль длинный, со сменой — «Размещение» → «Изменить параметры подключения».

## 6. Прочие секреты

- **Токен Cloudflare** (раздел «Сертификаты»): права «Zone → DNS → Edit» и «Zone → Zone → Read» только для зоны сайта; токен уровня всего аккаунта не нужен.
- **Почта** (уведомления, коды второго фактора): ящик, которому разрешена только отправка.
- **SMS-шлюз, RADIUS, SIEM**: ключ или учётная запись только для отправки сообщений или событий.
- **Базы данных UDS и Guacamole**: пользователь с правами только на свою базу, вход только с серверов системы.
