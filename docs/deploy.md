# Установка: профили и порядок

*Начало работы*

> Профили установки и порядок настройки по этапам: где в кабинете, что нужно заранее, как проверить.

## Профили установки

|  | Минимальная | Стандартная | Расширенная |
|----|----|----|----|
| **Для чего** | пилот, небольшой офис, стенд | рабочая установка в контуре организации | стандартная + вход сотрудников из интернета |
| **Отказоустойчивость** | нет: один сервер | каждый слой в паре или тройке, в разных зонах доступности | как стандартная; внешний вход тоже парный |
| **Серверы** | 1 ВМ: брокер, кабинет, СУБД, туннель, HTML5 | фронты ×2 (VIP), брокеры с кабинетом ×2, Galera ×3, туннели ×2 (VIP), шлюзы HTML5 ×2 | \+ в DMZ: пограничные фронты ×2 и внешние туннели ×2 с FIP |
| **Вход сотрудников** | по адресу сервера | внутреннее имя портала (vdi.компания.local) за VIP фронтов | внутреннее имя + публичное имя (my.поддомен) с DNS-балансировкой VK Cloud |
| **Платформы столов** | VK Cloud и/или VMware vSphere — в любом профиле, подключений каждого вида может быть несколько |  |  |
| **Переход** | → стандартная: новые ВМ, данные переносятся | → расширенная: на месте, добавляется DMZ |  |

Схемы каждого профиля и пути сеанса — [«Схемы архитектуры»](topology.md), требования — «Пререквизиты». Состав конкретной установки виден в «Состоянии системы»: страница строится из того, что подключено.

## Порядок настройки

Последовательность, в которой ничего не приходится переделывать: каждый этап опирается на предыдущие. Главная страница кабинета показывает те же шаги и что из них уже сделано.

0

**Инфраструктура (до установки)**Где: облако, домен, DNSЗаранее: всё со страницы «Пререквизиты»

- сети и группы безопасности слоёв, роутер с выходом в интернет (обновления, образы, Let's Encrypt)
- контроллеры домена; центр сертификации, если портал будет по внутреннему имени
- внутренние имена: портал → VIP фронтов, туннели → VIP туннелей; DNS подсети столов — контроллеры домена
- сервисные учётные записи: облако, чтение каталога, ввод в домен

1

**Каркас**Где: установщик (скрипты ролей)Заранее: ВМ Ubuntu 24.04 для каждой роли

- Galera ×3 → брокеры с кабинетом ×2 → фронты ×2 с VIP
- на всех серверах — агент нагрузки

Проверка: **«Состояние системы»**: фронты, кабинет, брокеры, СУБД — в норме

2

**Организация**Где: «Организация» (кнопка с названием вверху меню)

- название и код (код — в именах столов)
- часовой пояс
- адрес портала для сотрудников (внутреннее имя)
- запросы сотрудников — включить или выключить

3

**Платформа для столов**Где: **«Размещение»** → VK Cloud / VMware vSphereЗаранее: сервисная учётка облака (домен service-users) или vCenter

- подключение облака: проект, зона, сеть столов, группа безопасности столов
- vSphere: адрес vCenter, учётка, папка, пул ресурсов

Проверка: зелёная проверка у подключения

4

**Домен и пользователи**Где: **«Домен и пользователи»**Заранее: учётки чтения каталога и ввода в домен, корень CA контроллеров

- подключение каталога сразу по LDAPS с корнем CA (без TLS не будет смены пароля сотрудниками)
- «Проверить» у ввода в домен: панель создаёт и удаляет пробный компьютер в OU столов
- группы доступа (например, VDI-Users-…) и размещение столов по группам

Проверка: вход тестового сотрудника на портал

5

**Сертификат сайта**Где: **«Сертификаты»**Заранее: сертификат на имя портала (CA организации) или учётка DNS для Let's Encrypt

- загрузить сертификат или выпустить Let's Encrypt; фронты подхватят его сами

Проверка: фронты в «Сертификатах» — «актуален»

6

**Туннели**Где: **«Размещение»** → «Туннели UDS»Заранее: две чистые ВМ Ubuntu 24.04 в сети приложений

- группа туннелей: адрес для клиентов (имя туннелей) и VIP пары
- «Подключить сервер» ×2 — одноразовая команда на каждой ВМ
- корпоративные сети и способ подключения из них (через туннель или напрямую)
- транспорт по умолчанию — «Клиент UDS через туннель»

Проверка: у группы «держит VIP: …», оба сервера на связи

7

**Вход из браузера (по желанию)**Где: **«Размещение»** → «HTML5»Заранее: две чистые ВМ Ubuntu 24.04

- «Подключить шлюз» ×2; фронты добавят их в балансировку сами
- шаблон транспорта HTML5 (из него мастер пула делает транспорт «В браузере»)

Проверка: адреса входа для браузеров — «отвечает»

8

**Образ**Где: **«Образы»**Заранее: эталонная ВМ в сети столов с доступом к порталу

- команда подготовки на эталоне: агент UDS, агент «Программы и настройки», часовой пояс, остатки VMware Tools
- вариант «по имени» — с корнем CA организации; «по IP» — без проверки сертификата
- выключить эталон и добавить образ (ID ВМ)

Проверка: образ «доступен»

9

**Каталог и пул**Где: **«Каталоги машин»** → мастер

- образ, размер, сеть, вход (домен / без домена), группы доступа, транспорты, питание
- публикация версии, первые столы

Проверка: стол «готов», компьютер стола появился в OU домена

10

**Проверка сотрудником в контуре**Где: портал (адрес из «Организации»)Заранее: UDS Launcher на компьютере сотрудника

- вход доменной учёткой
- «Подключиться» (клиент UDS) и «В браузере»

11

**Вход из интернета (по желанию)**Где: **«Размещение»** → «Внешний вход»Заранее: поддомен, делегированный в VK Cloud DNS; DMZ с 4 ВМ и FIP; учётка VK Cloud DNS

- учётка VK Cloud DNS (роль «Администратор сети»)
- «Подключить пограничный фронт» ×2
- группа туннелей → гибридная (адрес для интернета + внутренний), «Подключить сервер» для внешних туннелей ×2
- публичные имена: портал и туннели; сертификат Let's Encrypt на публичное имя портала

Проверка: с телефона без VPN: портал, «Подключиться», «В браузере»

12

**Эксплуатация**Где: **«Состояние системы»**, **«Уведомления»**, **«Второй фактор»**

- уведомления администраторам, SIEM, второй фактор, профили сотрудников в S3, администраторы кабинета
- «Календари»: рабочие часы и праздники; в пуле — доступ по расписанию и действия (прогрев столов к началу дня, публикация ночью, сообщение о работах)
