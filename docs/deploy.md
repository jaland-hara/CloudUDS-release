# Установка в VK Cloud: профили инсталляции и порядок

*Начало работы*

> Пошагово от пустого проекта VK Cloud до первого стола: подготовка проекта, мастер установки, настройка в кабинете.

## Профили инсталляции

Профиль инсталляции — состав и размер серверной части CloudUDS в проекте VK Cloud: сколько ВМ, какие роли на них и есть ли отказоустойчивость. Не путать с профилями пользователей (папки сотрудников в S3).

| Профиль инсталляции | Минимальный | Базовый | Стандартный | Расширенный |
|----|----|----|----|----|
| **Для чего** | пилот, небольшая команда (до ~50 столов) | рабочая установка без отказоустойчивости | рабочая установка в контуре организации | стандартный + вход сотрудников из интернета |
| **Отказоустойчивость** | нет: одна ВМ | нет: по одной ВМ на роль | пары и Galera ×3 в разных зонах доступности | как у стандартного; внешний вход тоже парный |
| **ВМ в проекте** | 1: портал, кабинет, брокер, MariaDB, туннель, HTML5 | 5: фронт, брокер, БД, туннель, шлюз HTML5 (+2 в DMZ по желанию) | 11: фронты ×2 (VIP), брокеры ×2, Galera ×3, туннели ×2 (VIP), шлюзы HTML5 ×2 | 15: стандартный + пограничные фронты ×2 и внешние туннели ×2 в DMZ с плавающими IP |
| **Вход сотрудников** | из внутренней сети | из внутренней сети; из интернета — с узлами DMZ | внутреннее имя портала (vdi.компания.local) за VIP фронтов | внутреннее имя + публичное имя с DNS-балансировкой VK Cloud |
| **Установка мастером** | 14–19 мин | 22–25 мин | 32–45 мин | ~36 мин |
| **vCPU** | 8 | 14 (с DMZ — 18) | 30 | 38 |
| **RAM, ГБ** | 16 | 28 (с DMZ — 36) | 60 | 76 |
| **Диски SSD, ГБ** | 100 | 140 (с DMZ — 180) | 320 | 400 |
| **Плавающие IP** | 0 | 0 (с DMZ — 2) | 0 | 4 |

Ресурсы — только серверная часть, без ВМ установщика (2 vCPU, 4 ГБ RAM, 40 ГБ SSD) и без столов. Разбивка по ролям для расчёта стоимости — [«Что нужно до установки» → «Серверы и ресурсы по профилям инсталляции»](prereq.md).

Время — от новой ВМ установщика до конца проверок, без заполнения экранов (ещё 10–20 минут в первый раз). Смену профиля инсталляции мастер пока не делает: выбирайте профиль под целевую нагрузку. Схемы профилей инсталляции — [«Схемы архитектуры»](topology.md), требования — [«Что нужно до установки»](prereq.md).

Столы во всех профилях создаются в проекте VK Cloud. Свой VMware vSphere заказчика (опция, например на VK Cloud Bare Metal as a Service) подключается после установки в «Размещении» — [пулы в VMware vSphere (опция)](vsphere.md).

## 1. Подготовка в VK Cloud и в организации

Всё, что мастер установки не может сделать сам. Сети, группы безопасности, ВМ и плавающие IP он создаёт в проекте сам.

**1. Проект VK Cloud**

Где: консоль VK Cloud

- проект в нужном регионе; квоты под профиль инсталляции ([ресурсы по профилям](prereq.md)): ВМ, vCPU, RAM, диски, плавающие IP (4 для входа из интернета), группы безопасности, сети — плюс запас под столы
- сервисная учётная запись для мастера: «Управление доступами» → «Сервисные учётные записи», роли «Администратор ВМ», «Администратор сети», «Администратор сетевой безопасности» (или «Администратор проекта»); ID проекта — в настройках проекта
- учётная запись, под которой UDS будет создавать столы: можно ту же, для эксплуатации рекомендуется отдельная с ролью «Младший администратор ВМ»
- бакеты в «Объектном хранилище»: профили сотрудников и резервные копии, у каждого свой аккаунт S3 с доступом только к нему
- для входа из интернета (расширенный профиль инсталляции или базовый с DMZ): зона внешнего имени (например, поддомен my.компания.ru) делегирована в DNS VK Cloud; DNS-балансировку (GSLB) для проекта включает поддержка VK Cloud по запросу

**2. Связь с организацией**

Где: сеть организации, домен, DNS

- контроллеры домена доступны из проекта (VPN или прямое подключение к сети организации): LDAPS 636, Kerberos 88, DNS 53, SMB 445
- сети пользователей (офис, VPN) знают маршрут в проект: оттуда сотрудники ходят на 443 фронтов и туннелей
- учётные записи домена: чтение каталога и ввод столов в домен (права — [«Учётные записи и права»](accounts.md))
- решение по сертификату внутреннего имени: CA организации (AD CS) или корень установки, который мастер выпустит сам

**3. ВМ установщика**

Где: консоль VK Cloud, затем SSH на ВМ

Заранее: доступ ВМ к GitHub или пакет выпуска, принесённый заранее

- ВМ Ubuntu 24.04, 2 vCPU / 4 ГБ / 40 ГБ в проекте; проще всего — в сети с маршрутизатором, который мастер возьмёт и для узлов
- на ВМ: curl -fsSLO https://raw.githubusercontent.com/jaland-hara/CloudUDS-release/main/install.sh, затем sudo bash install.sh (последний выпуск) или sudo bash install.sh /путь/cloududs-X.Y.Z.tar без интернета; скрипт проверяет подпись пакета до распаковки
- скрипт печатает команду SSH-туннеля (ssh -L 8200:127.0.0.1:8200 ubuntu@\<ВМ\>) и ссылку входа в мастер; новая ссылка — sudo cloududs-installer link

Проверка: мастер открывается в браузере по ссылке через туннель

## 2. Мастер установки

Шесть экранов по порядку. Мастер хранит всё введённое: его можно закрыть и продолжить, любой шаг — повторить.

**4. Профиль инсталляции**

Где: мастер → «Профиль инсталляции»

- минимальный, базовый, стандартный или расширенный — мастер показывает схему, состав ВМ и размеры

**5. Подготовка облака**

Где: мастер → «Подготовка облака» → «Создать автоматически»

Заранее: сервисная учётная запись проекта (шаг 1)

- подключение к проекту: учётная запись, пароль, ID проекта, домен service-users → «Проверить подключение»
- что создать: префикс имён (все объекты — «префикс-…»), маршрутизатор (сеть установщика или новый с выходом в интернет), образ Ubuntu 24.04, зоны доступности, подсети слоёв и сети столов, тип дисков, семейство флейворов
- DNS узлов и DNS сети столов — контроллеры домена: столы входят в домен и находят портал по внутреннему имени
- сети пользователей — откуда открыть 443 к фронтам и туннелям; «Вход из интернета» — узлы DMZ и свободные плавающие IP проекта
- «Показать план» → «Создать ресурсы»: сети, группы безопасности с правилами (включая RDP и агент UDS к сети столов), порты VIP, диски, ВМ, плавающие IP; мастер ждёт, пока ВМ ответят по SSH

Проверка: план выполнен, все ВМ на связи

**6. Узлы и предпроверка**

Где: мастер → «Узлы и предпроверка»

- список узлов заполнен по созданным ВМ — «Сохранить и проверить узлы»
- на каждом узле: SSH и sudo, Ubuntu 24.04, размеры против профиля инсталляции, время, DNS, зеркало пакетов, свободные порты; затем каждая связь между ролями
- зеркала Ubuntu недоступны (бывает с плавающих IP VK Cloud) или интернет только через прокси организации — «Прокси для пакетов ОС»

Проверка: «предпроверка пройдена»; закрытая связь — правило группы безопасности (облако применяет правила с задержкой до минуты)

**7. Параметры**

Где: мастер → «Параметры»

Заранее: бакеты S3 и их ключи; имена портала

- название организации; внешнее имя портала (из интернета) и внутреннее (в DNS организации → VIP фронтов); VIP фронтов и туннелей — свободные адреса их подсетей
- сертификат: Let's Encrypt через зону VK DNS или свой (загрузить в кабинете; до этого — временный)
- имена, которые узлы должны знать без DNS (контроллеры домена): dc01.corp.local:10.0.0.10
- S3: бакет профилей и бакет резервных копий с ключами (один общий бакет — только для тестов)
- облако для столов: учётная запись UDS — та же, что у мастера, или отдельная

**8. Установка**

Где: мастер → «Установка» → «Начать установку»

- 11 шагов: подготовка узлов (обновление ОС, Docker) → образы контейнеров из пакета → Galera → брокеры UDS → кабинет и портал → фронты с VIP → туннели, шлюзы HTML5 и узлы DMZ через кабинет → агенты нагрузки → настройки кабинета (подключение облака для столов, бакеты, транспорты, внешний вход) → сертификат публичного имени → проверки
- после ошибки журнал на экране называет причину; устраните её и нажмите «Продолжить» — мастер начнёт с упавшего шага

Проверка: шаг «Проверки» — все пункты «ok»

**9. Результат**

Где: мастер → «Результат»

- адреса кабинета, портала, фронтов и VIP туннелей; пароль администратора кабинета и UDS — смените после первого входа
- корень сертификатов установки — скачайте, если на внутреннем имени нет сертификата CA организации
- ВМ установщика храните: через неё идут обновления; между обновлениями её можно выключить — платится только диск

## 3. Настройка в кабинете

Главная страница кабинета показывает эти шаги и что из них уже сделано. Туннели, шлюзы HTML5, внешний вход и подключение облака мастер уже настроил — в «Размещении» их нужно только проверить.

**10. DNS и сертификат внутреннего имени**

Где: DNS организации, **«Сертификаты»**

- записи в DNS организации: внутреннее имя портала → VIP фронтов, имя туннелей → VIP туннелей (адреса — на экране «Результат»)
- сертификат на внутреннее имя от CA организации — загрузить в «Сертификаты»; или раздать корень установки компьютерам сотрудников групповой политикой

Проверка: портал по внутреннему имени открывается без предупреждения браузера

**11. Организация**

Где: «Организация» (кнопка с названием вверху меню)

- код (входит в имена столов), часовой пояс, адрес портала для сотрудников
- запросы сотрудников — включить или выключить

**12. Облако для столов**

Где: **«Размещение»** → VK Cloud

- подключение, созданное мастером: проект, зона, сеть и группа безопасности столов по умолчанию
- ещё проекты VK Cloud — «Подключить»; свой vSphere заказчика (опция) — здесь же

Проверка: зелёная проверка у подключения

**13. Домен и пользователи**

Где: **«Домен и пользователи»**

Заранее: учётки чтения каталога и ввода в домен, корень CA контроллеров

- каталог сразу по LDAPS с корнем CA (без TLS сотрудники не смогут сменить пароль)
- «Проверить» у ввода в домен: кабинет создаёт и удаляет пробный компьютер в OU столов
- группы доступа (например, VDI-Users-…) и размещение столов по группам; без домена — собственные пользователи

Проверка: вход тестового сотрудника на портал

**14. Образ**

Где: **«Образы»**

Заранее: ВМ в сети столов проекта (подсеть «префикс-vdi») с доступом к порталу

- ВМ из образа VK Cloud (Windows — из ISO и по лицензии организации), нужные программы
- команда подготовки на ВМ: агент UDS, агент «Программы и настройки», часовой пояс; вариант «по имени» — с корнем CA, «по IP» — без проверки сертификата
- выключить ВМ и «Добавить образ» по ID ВМ — кабинет снимет тома-шаблоны

Проверка: образ «доступен»

**15. Каталог и пул**

Где: **«Каталоги машин»** → мастер пула

- образ, размер, тип диска, сеть, вход (домен / без домена), группы доступа, транспорты, питание
- публикация версии, первые столы — через 3–10 минут

Проверка: стол «готов», компьютер стола появился в OU домена

**16. Проверка сотрудником**

Где: портал (адрес из «Организации»)

Заранее: клиент CloudUDS на компьютере сотрудника (скачивается с портала)

- изнутри сети: вход доменной учёткой, «Подключиться» (приложение) и «В браузере»
- с входом из интернета — то же с телефона или ноутбука без VPN по публичному имени

**17. Резервные копии**

Где: **«Резервное копирование»**

- включить ежедневную копию в бакет S3
- **ключ восстановления** показывается один раз — сохраните его вне кабинета

Проверка: «Сделать копию сейчас» — копия появилась

**18. Безопасность и эксплуатация**

Где: **«Безопасность»**, **«Уведомления»**, **«Второй фактор»**

- «Сертификаты узлов»: включить mTLS, проверить сеансы, затем «Требовать»
- защита входа, второй фактор для сотрудников и администраторов, доверенные сети; с входом из интернета — закрыть кабинет для интернета (джамп-хост или VPN)
- уведомления администраторам (почта, Telegram), SIEM, профили сотрудников в S3, администраторы кабинета
- «Календари»: рабочие часы и праздники; в пуле — доступ по расписанию, прогрев столов к началу дня, публикация ночью

Обновление работающей установки — тем же мастером на ВМ установщика: [«Обновления»](updates.md) и UPGRADE.md в репозитории выпусков.
