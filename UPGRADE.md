# Обновление боевой установки

Для администратора установки VDI (OpenUDS + кабинет) в VK Cloud. Проверено на тестовом стенде: обновление 0.1.0-rc.7 → 0.1.0-rc.8, 15 узлов, 6 минут, столы и сеансы не пострадали.

## 1. Что и чем обновляется

| Что | Как | Нужен ли установщик |
|---|---|---|
| Брокеры UDS, кабинет и портал, фронты, Galera | мастер установки, режим «Обновление»: по одному узлу | да |
| Туннели, шлюзы HTML5, пограничные фронты, внешние туннели | агенты узлов сами берут новые образы из кабинета: по одному узлу роли, при неудаче возвращают прежний образ | нет (мастер только дожидается их) |
| Агенты нагрузки на узлах, агенты на столах | обновляются сами из кабинета | нет |
| Пакеты Ubuntu и ядро узлов | мастер, «Обновить ОС узлов»: по одному узлу с перезагрузкой | да |
| Сертификаты сайта (Let's Encrypt) | кабинет продлевает сам | нет |
| Агент UDS в образах столов | новая подготовка эталона («Образы → Подготовить»), затем новая версия пула | нет |

Установщик держит SSH-ключ ко всем узлам и секреты установки, поэтому обновление идёт из него, а не из кабинета: кабинет смотрит в интернет и не должен иметь root-доступа к узлам. Между обновлениями ВМ установщика можно выключить: тогда платится только её диск.

## 2. Перед обновлением

1. Прочитайте заметки к выпуску (https://github.com/jaland-hara/CloudUDS-release/releases): изменения, особые шаги, минимальная версия, с которой можно обновляться.
2. Кабинет → «Состояние системы»: всё зелёное. Мастер это тоже проверит и при красном остановится.
3. Кабинет → «Резервное копирование» → «Сделать копию сейчас». Без копии за последние сутки мастер не начнёт обновление (флажок «без копии» — только для тестовых стендов). Ключ восстановления должен быть у вас, а не только в кабинете.
4. Выберите окно. Сеансы в туннелях обновление не рвёт, но при перезапуске брокера вход в портал и кабинет может на несколько секунд не пройти — лучше вне часов пик.
5. Включите ВМ установщика, если она была выключена.

## 3. Обновление

1. Обновите сам мастер на ВМ установщика:
   ```
   sudo cloududs-installer              # последний выпуск
   sudo cloududs-installer 0.1.0-rc.9   # или конкретная версия
   ```
   Без интернета на ВМ: принесите файл `cloududs-X.Y.Z.tar` и выполните `sudo cloududs-installer /путь/cloududs-X.Y.Z.tar`. Подпись и контрольные суммы проверяются до распаковки. Данные мастера (параметры, секреты, ключи) сохраняются.
2. Откройте мастер (SSH-туннель, `sudo cloududs-installer link` — новая ссылка входа) → «Установка» → блок «Обновление». Там видно: установленная версия, версия мастера, шаги.
3. Нажмите «Обновить до X.Y.Z». Шаги:

   | # | Шаг | Что происходит |
   |---|---|---|
   | 1 | Перед обновлением | все проверки зелёные, есть копия кабинета за сутки |
   | 2 | Образы | новые образы загружаются на брокеры, ничего не перезапускается |
   | 3 | Брокеры по одному | первый применяет миграции базы UDS, второй в это время обслуживает |
   | 4 | Кабинет и портал по одному | заодно новые образы туннелей и шлюзов попадают в дистрибутив кабинета |
   | 5 | Фронты по одному | первым фронт без VIP, держатель VIP — последним: VIP переезжает один раз и уже на обновлённый фронт |
   | 6 | Galera | учётки приложений приводятся к выпуску, узлы БД не перезапускаются |
   | 7 | Туннели и шлюзы | мастер ждёт (до часа), пока агенты узлов обновят их по одному |
   | 8 | Настройки кабинета | права портала, транспорты, подключения — к выпуску |
   | 9 | Проверки | то же, что после установки; затем записывается новая версия |

4. Если шаг упал: журнал на экране — причина. Устраните её и нажмите «Продолжить обновление»: мастер начнёт с упавшего шага (сделанные шаги повторно не выполняются). Любой шаг можно повторять — это безопасно.

## 4. После обновления

- Кабинет → «Состояние системы»: всё зелёное, версии узлов одинаковые.
- Вход на портал сотрудником, открытие стола клиентом UDS и из браузера.
- Кабинет → «Уязвимости»: новые находки после обновления образов.
- Выключите ВМ установщика, если она не нужна.

## 5. Откат

- **Код без изменений базы** (заметки к выпуску это говорят явно): обновите мастер до прежней версии (`sudo cloududs-installer <прежняя>`) и запустите «Обновление» — узлы вернутся на прежние образы тем же порядком.
- **Выпуск менял базу UDS или кабинета** (миграции): обратных миграций нет. Откат — восстановление из резервной копии, сделанной перед обновлением (кабинет → «Резервное копирование» → «Восстановление»), на прежней версии.
- **Узел туннеля или шлюза не принял образ**: агент узла сам возвращает прежний образ; кабинет → «Размещение» покажет ошибку образа у узла.

## 6. Обновление ОС узлов (раз в месяц и по критичным уязвимостям)

Мастер → «Установка» → «Обновить ОС узлов». Порядок: узлы Galera по одному (следующий — только когда кластер снова Synced), брокеры, фронты (держатель VIP последним), туннели, шлюзы, пограничные (с паузой, чтобы балансировка DNS вернула узел). Перед каждым узлом проверяется, что он здоров, после — что его роль снова работает; если нет, мастер останавливается и остальные узлы не трогает.

## 7. Установщик тоже надо беречь

В `/var/lib/cloududs-installer` лежат параметры установки, зашифрованные секреты и SSH-ключ к узлам. Без них обновлять придётся вручную. Пока в мастере нет автоматической копии — после установки и каждого обновления сохраните каталог зашифрованным вне ВМ, например:
```
sudo tar czf - -C /var/lib cloududs-installer | gpg --symmetric --cipher-algo AES256 > cloududs-installer-$(date +%F).tgz.gpg
```
и положите в хранилище паролей/секретов организации. Восстановление: новая ВМ, `install.sh` той же версии, распаковать каталог на место, `sudo cloududs-installer restart`.

## 8. Что пока не автоматизировано

- Уведомление в кабинете «вышла новая версия» — смотрите страницу выпусков.
- Автоматическая зашифрованная копия данных установщика в S3.
- Проверка шага 7 на выпуске, где образы туннелей и шлюзов действительно меняются (на rc.7 → rc.8 они совпадали).
